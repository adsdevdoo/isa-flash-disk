# Программы: Option ROM и утилиты DOS

Статус: **версия 1.2: чтение и запись диска через INT 13h, формат диска 3 (перезапись блоков с ротацией,
защита от сбоя питания). Проверена на модели карты в эмуляторе 8086 (129 проверок), на железе не проверялась.**
Готовые файлы — в [dist/](../dist/), исходники — `firmware/` и `software/dos/` (NASM, только инструкции 8086).

| Файл | Что делает |
|---|---|
| `FLASHROM.BIN` | Option ROM 8 КБ: диск 80h через INT 13h (чтение и запись), загрузка через INT 19h |
| `FLINFO.COM` | ищет карту, показывает ПЗУ, ID микросхем, геометрию, формат и карту блоков; `/J` — проверка JP1 |
| `FLFORMAT.COM` | записывает ПЗУ (с портом карты) и дескриптор диска в блок 0; `/E` — стереть диск и разметить заново |
| `FLWRITE.COM` | пишет файл во флеш с проверкой; `/D` — образ диска, `/O:n` — с блока n (hex) |
| `FLREAD.COM` | читает флеш в файл; `/D` — только диск (образ для FLWRITE /D и для эмуляторов ПК) |
| `MBR.BIN`, `VBRSTUB.BIN` | загрузчик MBR и загрузочный сектор раздела без DOS, их использует `tools/mkdisk.py` |

Все утилиты принимают `/M:сегмент` и `/P:порт`. Без них окно ищется по сигнатуре ПЗУ в C800h…F400h, а порт
берётся из ПЗУ; на чистой карте — CC00h и 2A0h.

## Первая запись ПЗУ

ПЗУ хранится в той же флеш, что и диск, но для его записи карте собственное ПЗУ не нужно. Утилиты работают
с картой напрямую, через порты и окно. На новой карте BIOS не находит ПЗУ и загружается как обычно, а утилиты
ищут карту на CC00h и 2A0h (или там, куда указывают `/M:` и `/P:`, если переключатели стоят иначе).
Так же восстанавливается карта после неудачной записи блока 0: BIOS отбрасывает ПЗУ с неверной контрольной суммой
(XT 5-10), карта остаётся доступной утилитам.

1. Переключатели — по таблице на плате (по умолчанию окно CC000h, порты 2A0h). JP1 надеть.
2. Загрузить DOS с дискеты, на которой лежат `FLINFO.COM`, `FLFORMAT.COM`, `FLWRITE.COM` и `FLASHROM.BIN`.
3. `FLINFO /J`: должны найтись две (или одна) 28F008SA и «JP1: fitted». «Option ROM: not found» на новой карте —
   нормально.
4. `FLFORMAT FLASHROM.BIN /E` — ПЗУ, дескриптор и пустой диск. После перезагрузки ПЗУ пишет
   `ISA Flash Disk: 1905 KB, drive 80h, …`.

Снятые с модуля микросхемы могут хранить старые данные. BIOS выполняет только ПЗУ с сигнатурой 55AAh и нулевой
контрольной суммой (XT 5-10), поэтому случайные данные почти наверняка будут пропущены. Если компьютер всё же
зависнет при старте, можно временно переставить окно SW1 туда, где BIOS ПЗУ не ищет: у BIOS IBM XT это
C0000h…C6000h (если в машине нет EGA/VGA). Затем загрузиться и запустить `FLFORMAT … /M:C000`. После записи
вернуть SW1.

## Как сделать загрузочный флеш-диск

1. Записать ПЗУ, как описано выше.
2. На ПК собрать образ диска:

   ```bash
   python tools/mkdisk.py DISK.IMG --chips 2 --boot DOS622.IMG --add AUTOEXEC.BAT CONFIG.SYS --split 640
   ```

   `--boot` — образ загрузочной дискеты MS-DOS 4.0–6.22, PC DOS 4+ или FreeDOS: с неё берутся загрузочный
   сектор и системные файлы. Загрузочные сектора DOS 3.x (без расширенного BPB) поддержаны **экспериментально**:
   mkdisk правит только BPB DOS 3.x (0Bh…1Dh, 16-битное число скрытых секторов) и байт диска 1FDh = 80h,
   на настоящей DOS 3.x это не проверялось. `--split` режет образ на части под дискеты (целыми блоками
   по 127 секторов, 63.5 КБ) и печатает команды `FLWRITE … /D /O:…`.
3. На ретро-машине выполнить эти команды `FLWRITE` и перезагрузить: без дискеты в A: загрузка пойдёт
   с флеш-диска.

Перемычку JP1 можно оставить, если нужна запись на диск из DOS (`COPY`, редакторы, `FORMAT C:`). Без JP1 диск
доступен только для чтения: запись возвращает «write protect».

## Формат диска 3: запись из DOS без потерь при сбое питания

28F008SA записывает только нули (1 → 0), а единицы возвращает только стирание целого блока 64 КБ (DS с. 16).
Сектор диска — 512 байт, поэтому изменить сектор «на месте» обычно нельзя.

**Как разложен диск.** Диск разрезан на логические блоки по 127 секторов. Каждый логический блок лежит в одном
блоке флеш 64 КБ: секторы 0…126 — данные, сектор 127 — заголовок (номер логического блока, счётчик поколений,
байт «копия целая»). Физических блоков на один больше, чем логических: один всегда свободен.

| | 1 микросхема | 2 микросхемы |
|---|---:|---:|
| Блоков флеш под диск | 15 (блоки 1…15) | 31 (блоки 1…31) |
| Логических блоков | 14 | 30 |
| Объём | 1778 секторов, **889 КБ** | 3810 секторов, **1905 КБ** |
| Геометрия C/H/S | 127/2/7 | 127/2/15 |

**Данные инвертированы**: во флеш лежит NOT от каждого байта. Стёртая флеш читается как нули, поэтому запись
в свободное место (новые файлы, новые записи каталога и FAT) только сбрасывает биты и программируется на месте,
без стирания.

**Если нужно стирание**, ПЗУ не трогает текущую копию блока:

1. стирает свободный блок;
2. копирует в него блок вместе с новыми секторами;
3. последним пишет заголовок с поколением на 1 больше, байт «копия целая» — самым последним;
4. старая копия становится свободным блоком (её сотрут при следующей перезаписи).

При включении ПЗУ читает заголовки всех блоков и для каждого логического блока берёт целую копию с самым большим
поколением. Поэтому при сбое питания на любом шаге остаётся либо старая копия блока, либо новая — целиком.
Теряется только сектор, который в этот момент записывался, как на обычном винчестере. В эмуляторе это проверено
отключением питания после 0, 1, 2, … операций до последней, в том числе внутри переноса блока (ниже).

**Износ.** Флеш выдерживает 100 000 стираний на блок (DS с. 16). Одна ротация гоняла бы часто переписываемый блок
(FAT, каталог) между двумя физическими блоками. Поэтому после каждой перезаписи с поколением, кратным 8, ПЗУ
переносит ещё один логический блок по кругу, и стирания расходятся по всем блокам. По моделированию ресурс
в 22–27 раз больше, чем без переноса, ценой примерно 14 % лишних стираний. В эмуляторе 64 перезаписи одного
сектора дали не больше 12 стираний на блок (без переноса было бы 32).

**Время.** Перезапись блока — одно стирание (тип. 1.6 с, до 10 с, DS с. 33–34) и копирование 63.5 КБ; на XT
это секунды, DOS в это время ждёт. Запись на месте идёт со скоростью программирования байтов.

**Утилиты.** `FLWRITE /D` разрезает обычный образ диска на логические блоки и пишет каждый изменённый блок так же,
в свободный блок с новым заголовком; одинаковые блоки пропускает. `FLREAD /D` собирает образ обратно по карте
блоков. Образ на ПК — обычный образ диска, его можно открыть в эмуляторе ПК. После записи `FLWRITE` и `FLFORMAT`
просят резидентное ПЗУ перечитать карту блоков (INT 13h AH=F1h), чтобы оно не писало по старой карте.
Если DOS до этого уже работала с диском C:, компьютер нужно перезагрузить: её буферы устарели.

Диск, записанный версиями 1.0 и 1.1 (форматы 1 и 2), нужно стереть и записать заново: `FLFORMAT FLASHROM.BIN /E`,
потом `FLWRITE … /D`. ПЗУ 1.2 такой диск не подключает и пишет `no disk (format 3), run FLFORMAT /E`.

## Как устроено

- **Option ROM** ([flashrom.asm](../firmware/option-rom/flashrom.asm)). Инициализация выполняется прямо из окна,
  отнимает **3 КБ** у основной памяти (40h:13h) и копирует туда резидентную часть: INT 13h, INT 19h, чтение
  дескриптора и карты блоков, запись и стирание, буфер сектора. Банки переключает только код в ОЗУ, иначе ПЗУ
  исчезло бы из окна. Каждый сектор читается и программируется с запретом прерываний, после него сразу снова
  банк 0 (правило банка 0, [architecture.md](architecture.md)). Во время стирания прерывания разрешены,
  тайм-аут 22 с.
- **INT 13h:** 00h, 01h, 02h, 03h, 04h, 05h, 08h, 09h, 0Ch, 0Dh, 10h, 11h, 15h и служебная F1h (перечитать карту
  блоков, BX = 464Ch). 05h (форматирование дорожки) ничего не делает и возвращает успех. Ошибки записи:
  03h — JP1 снята, BBh — ошибка автомата флеш (SR.4/SR.5), 80h — тайм-аут. Чужие номера дисков уходят
  в прежний обработчик BIOS.
- **INT 19h** ставится, только если флеш стал диском 80h: дискета A: (4 попытки), потом MBR флеш-диска
  с проверкой 55AAh, потом штатная загрузка BIOS.
- **Утилиты** ([software/dos/](../software/dos/)) выполняют запись из ОЗУ, включают VPP только на время записи,
  проверяют SR.3/4/5 после каждой операции (DS с. 18–21), тайм-аут стирания 22 с при максимуме 10 с (DS с. 34),
  по Ctrl-Break и при любом выходе возвращают карту в безопасное состояние: Read Array, CTRL = 0, BANK = 0.
  Без `/D` `FLWRITE` и `FLREAD` работают с сырой флеш целиком (блоки по 64 КБ от адреса 0).

## Проверка перемычки JP1

Порта чтения на карте нет, поэтому `FLINFO /J` и все записывающие утилиты включают VPP и программируют `FFh`
в первый байт ПЗУ. Запись меняет биты только из 1 в 0, поэтому `FFh` ничего не меняет. SR.3 = 1 значит, что VPP
ниже нормы и JP1 снята (DS с. 18). Без JP1 запись через INT 13h возвращает AH = 03h до любых изменений.
В эмуляторе проверено; на железе — подтвердить на прототипе.

## Сборка и тесты

```bash
python tools/build_dos.py путь/к/nasm.exe
```

```bash
pip install unicorn==2.1.4
```

```bash
python tools/emu/test_isaflash.py
```

Тест (`tools/emu/`) гоняет настоящие `.COM` и ПЗУ на эмуляторе 8086 с моделью карты и двух 28F008SA:
FLFORMAT без и с JP1, FLINFO, FLWRITE /D (запись, повтор без изменений, изменение одного блока, запись частями,
запись под резидентным ПЗУ), FLREAD, инициализацию ПЗУ, все функции INT 13h, запись через INT 13h (без JP1,
на месте, с переносом блока, через границы логических блоков и микросхем, за концом диска), отключение питания
на каждом этапе перезаписи и переноса блока, распределение стираний, INT 19h, загрузку через MBR и то, что mkdisk
правит в загрузочных секторах DOS 4+ и DOS 3.x. Два варианта: 2 микросхемы на 2A0h/CC00h и 1 микросхема
на 300h/D000h. Модель функциональная: тайминги шины ISA, времена записи и стирания, недостёртый блок при сбое
во время стирания и поведение конкретных BIOS она не проверяет.
