# Программы: Option ROM и утилиты DOS

Статус: **версия 1.1: чтение и запись диска через INT 13h. Проверена на модели карты в эмуляторе 8086
(112 проверок), на железе не проверялась.**
Готовые файлы — в [dist/](../dist/), исходники — `firmware/` и `software/dos/` (NASM, только инструкции 8086).

| Файл | Что делает |
|---|---|
| `FLASHROM.BIN` | Option ROM 8 КБ: диск 80h через INT 13h (чтение и запись), загрузка через INT 19h |
| `FLINFO.COM` | ищет карту, показывает ПЗУ, ID микросхем, геометрию и формат диска; `/J` — проверка перемычки JP1 |
| `FLFORMAT.COM` | записывает ПЗУ (с портом карты) и дескриптор диска в блок 0; `/E` — стереть весь диск |
| `FLWRITE.COM` | пишет файл во флеш поблочно с проверкой; `/D` — образ диска, `/O:n` — с блока n (hex) |
| `FLREAD.COM` | читает флеш в файл; `/D` — только диск (образ для FLWRITE /D и для эмуляторов ПК) |
| `MBR.BIN`, `VBRSTUB.BIN` | загрузчик MBR и загрузочный сектор раздела без DOS, их использует `tools/mkdisk.py` |

Все утилиты принимают `/M:сегмент` и `/P:порт`. Без них окно ищется по сигнатуре ПЗУ в C800h…F400h, а порт
берётся из ПЗУ; на чистой карте — CC00h и 2A0h.

## Первая запись ПЗУ

ПЗУ хранится в той же флеш, что и диск, но для его записи карте собственное ПЗУ не нужно. Утилиты работают
с картой напрямую, через порты и окно. На новой карте BIOS не находит ПЗУ и загружается как обычно, а утилиты
ищут карту на CC00h и 2A0h (или там, куда указывают `/M:` и `/P:`, если переключатели стоят иначе).
Так же восстанавливается карта после неудачной записи блока 0: BIOS отбрасывает ПЗУ с неверной контрольной суммой
(XT 5-10), карта остаётся доступной утилитам.

1. Переключатели — по таблице на плате (по умолчанию окно CC000h, порты 2A0h). JP1 надеть.
2. Загрузить DOS с дискеты, на которой лежат `FLINFO.COM`, `FLFORMAT.COM`, `FLWRITE.COM` и `FLASHROM.BIN`.
3. `FLINFO /J`: должны найтись две (или одна) 28F008SA и «JP1: fitted». «Option ROM: not found» на новой карте —
   нормально.
4. `FLFORMAT FLASHROM.BIN /E` — ПЗУ, дескриптор и пустой диск. После перезагрузки ПЗУ пишет
   `ISA Flash Disk: 1920 KB, drive 80h, …`.

Снятые с модуля микросхемы могут хранить старые данные. BIOS выполняет только ПЗУ с сигнатурой 55AAh и нулевой
контрольной суммой (XT 5-10), поэтому случайные данные почти наверняка будут пропущены. Если компьютер всё же
зависнет при старте, можно временно переставить окно SW1 туда, где BIOS ПЗУ не ищет: у BIOS IBM XT это
C0000h…C6000h (если в машине нет EGA/VGA). Затем загрузиться и запустить `FLFORMAT … /M:C000`. После записи
вернуть SW1.

## Как сделать загрузочный флеш-диск

1. Записать ПЗУ, как описано выше.
2. На ПК собрать образ диска:

   ```bash
   python tools/mkdisk.py DISK.IMG --chips 2 --boot DOS622.IMG --add AUTOEXEC.BAT CONFIG.SYS --split 640
   ```

   `--boot` — образ загрузочной дискеты MS-DOS 4.0–6.22, PC DOS 4+ или FreeDOS: с неё берутся загрузочный
   сектор и системные файлы. Загрузочные сектора DOS 3.x (без расширенного BPB) поддержаны **экспериментально**:
   mkdisk правит только BPB DOS 3.x (0Bh…1Dh, 16-битное число скрытых секторов) и байт диска 1FDh = 80h,
   на настоящей DOS 3.x это не проверялось. `--split` режет образ на части под дискеты и печатает команды
   `FLWRITE … /D /O:…`.
3. На ретро-машине выполнить эти команды `FLWRITE` и перезагрузить: без дискеты в A: загрузка пойдёт
   с флеш-диска.

Перемычку JP1 можно оставить, если нужна запись на диск из DOS (`COPY`, редакторы, `FORMAT C:`). Без JP1 диск
доступен только для чтения: запись возвращает «write protect».

## Запись из DOS (INT 13h, функция 03h)

Блок стирания 28F008SA — 64 КБ, сектор диска — 512 байт, запись только сбрасывает биты (1 → 0), а 1
возвращает только стирание всего блока (DS с. 16). Поэтому, начиная с версии 1.1, диск хранится в **формате 2**:

- **Данные инвертированы**: во флеш лежит NOT от каждого байта. Стёртая флеш (FFh) читается как нули, поэтому
  запись в свободное место и любая запись, которая только добавляет единицы в данные, программируется на месте,
  без стирания. Это быстро (DOS пишет новые файлы в пустые кластеры, а FAT при выделении кластеров меняется
  в ту же сторону).
- **Запасной блок** — последний блок 64 КБ флеш (31 на двух микросхемах, 15 на одной). Если хоть один бит
  должен измениться из 0 в 1, ПЗУ переписывает блок через него: стирает запасной, копирует туда блок с новыми
  секторами, стирает блок, копирует обратно. Буфер 64 КБ в ОЗУ не нужен, ПЗУ занимает 2 КБ основной памяти.
- Объём диска из-за запасного блока меньше на 64 КБ: **1920 КБ** (60 × 4 × 16) на двух микросхемах,
  **896 КБ** (28 × 4 × 16) на одной.

Перезапись блока на XT занимает секунды (два стирания, каждое тип. 1.6 с и до 10 с, DS с. 33–34, и копирование 64 КБ дважды),
DOS в это время ждёт. Если в этот момент пропадёт питание или нажать Ctrl-Alt-Del, блок может остаться
стёртым: его содержимое лежит в запасном блоке, но автоматически эта версия его не восстанавливает. Поэтому
нужна резервная копия (`FLREAD КОПИЯ.IMG /D`) и не стоит выключать машину, пока горит индикатор записи DOS
(на карте его нет; ориентир — ожидание после команды записи).

Без JP1 VPP ниже нормы, автомат флеш выставляет SR.3, и ПЗУ возвращает AH = 03h до любых изменений:
в эмуляторе это проверено и для записи на месте, и для записи со стиранием.

`FLWRITE /D` и `FLREAD /D` сами инвертируют данные, поэтому образ на ПК — обычный образ диска: его можно
открыть в эмуляторе ПК или в программах для образов. Диск, записанный версией 1.0 (формат 1, без инверсии),
нужно стереть и записать заново: `FLFORMAT FLASHROM.BIN /E`, потом `FLWRITE … /D`. `FLINFO` показывает формат
диска и номер запасного блока, ПЗУ 1.1 диск формата 1 не подключает.

## Как устроено

- **Option ROM** ([flashrom.asm](../firmware/option-rom/flashrom.asm)). Инициализация выполняется прямо из окна,
  отнимает 2 КБ у основной памяти (40h:13h) и копирует туда резидентную часть: INT 13h, INT 19h, чтение
  дескриптора, запись и стирание. Банки переключает только код в ОЗУ, иначе ПЗУ исчезло бы из окна. Каждый
  сектор читается и программируется с запретом прерываний, после него сразу снова банк 0 (правило банка 0,
  [architecture.md](architecture.md)). Во время стирания прерывания разрешены, тайм-аут 22 с.
- **INT 13h:** 00h, 01h, 02h, 03h, 04h, 05h, 08h, 09h, 0Ch, 0Dh, 10h, 11h, 15h. 05h (форматирование дорожки)
  ничего не делает и возвращает успех. Ошибки записи: 03h — JP1 снята, BBh — ошибка автомата флеш (SR.4/SR.5),
  80h — тайм-аут. Чужие номера дисков уходят в прежний обработчик BIOS.
- **INT 19h** ставится, только если флеш стал диском 80h: дискета A: (4 попытки), потом MBR флеш-диска
  с проверкой 55AAh, потом штатная загрузка BIOS.
- **Утилиты** ([software/dos/](../software/dos/)) выполняют запись из ОЗУ, включают VPP только на время записи,
  проверяют SR.3/4/5 после каждой операции (DS с. 18–21), тайм-аут стирания 22 с при максимуме 10 с (DS с. 34),
  по Ctrl-Break и при любом выходе возвращают карту в безопасное состояние: Read Array, CTRL = 0, BANK = 0.
- **FLWRITE** пропускает одинаковые блоки 64 КБ, стирает блок только если какой-то бит должен стать 1,
  пишет только отличающиеся байты и сверяет каждый банк. С `/D` не трогает блок 0 и запасной блок.

## Проверка перемычки JP1

Порта чтения на карте нет, поэтому `FLINFO /J` и все записывающие утилиты включают VPP и программируют `FFh`
в первый байт ПЗУ. Запись меняет биты только из 1 в 0, поэтому `FFh` ничего не меняет. SR.3 = 1 значит, что VPP
ниже нормы и JP1 снята (DS с. 18). В эмуляторе проверено; на железе — подтвердить на прототипе.

## Сборка и тесты

```bash
python tools/build_dos.py путь/к/nasm.exe
```

```bash
pip install unicorn==2.1.4
```

```bash
python tools/emu/test_isaflash.py
```

Тест (`tools/emu/`) гоняет настоящие `.COM` и ПЗУ на эмуляторе 8086 с моделью карты и двух 28F008SA:
FLFORMAT без и с JP1, FLINFO, FLWRITE (запись, повтор без изменений, изменение со стиранием, запись частями),
FLREAD, инициализацию ПЗУ, все функции INT 13h (в том числе через границу U1/U2), запись через INT 13h
(без JP1, на месте, со стиранием через запасной блок, через границу блоков 64 КБ и микросхем, за концом диска),
INT 19h, загрузку через MBR и то, что mkdisk правит в загрузочных секторах DOS 4+ и DOS 3.x. Два варианта:
2 микросхемы на 2A0h/CC00h и 1 микросхема на 300h/D000h. Модель функциональная: тайминги шины ISA, времена
записи и стирания и поведение конкретных BIOS она не проверяет.
