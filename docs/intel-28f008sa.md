## Маркировка микросхем проекта

На модуле стоят **PA28F008SA**. По таблице заказа (DS, с. 42):

- `PA` — 44-выводной корпус PSOP, коммерческий диапазон температур (0…+70 °C);
- `TB` — тот же PSOP-44, расширенный диапазон;
- `E` — TSOP-40 (не наш случай).

Допустимые варианты PSOP: **PA28F008SA-85** и **PA28F008SA-120** (суффикс — время доступа в нс).
Суффикс на наших микросхемах нужно переписать с корпуса. Для ISA подходят оба (см. [isa-interface.md](isa-interface.md)).

## Организация памяти

- 8 Мбит = 1 048 576 байт, организация 1M × 8 (DS, с. 1, 5).
- 16 блоков по 64 Кбайт, каждый стирается независимо (DS, с. 5, рис. 5 на с. 10).
- Граница блока — адреса `x0000h`, блок N занимает `N0000h…NFFFFh`.
- Шина данных только 8 бит, режима ×16 нет.

## Назначение выводов (DS, табл. 1, с. 7)

| Сигнал | Тип | Назначение |
|---|---|---|
| A0–A19 | вход | Адрес. При записи защёлкивается микросхемой. |
| DQ0–DQ7 | вход/выход | Данные и команды. Третье состояние при CE# или OE# высоком. |
| CE# | вход | Выбор микросхемы, активный низкий. Высокий — режим standby. |
| OE# | вход | Разрешение выходов при чтении. |
| WE# | вход | Запись в интерфейс команд (CUI). Адрес и данные защёлкиваются **по фронту** WE#. |
| RP# | вход | Сброс / глубокое энергосбережение. Низкий уровень сбрасывает автомат записи и **запрещает запись и стирание**. |
| RY/BY# | выход | Готовность автомата записи. Всегда активный КМОП-выход, в третье состояние не переходит. |
| VPP | питание | Напряжение записи и стирания. При VPP < VPPL max содержимое изменить нельзя. |
| VCC | питание | 5 В ±10 % (или ±5 % для режима High Speed у -85). |

## Логические уровни (DS, с. 24–25)

- VIL: −0.5…0.8 В; VIH: 2.0 В…VCC + 0.5 В. **Входы ТТЛ-совместимые**, можно подключать к сигналам ISA напрямую.
- VOL ≤ 0.45 В при IOL = 5.8 мА; VOH ≥ 2.4 В при IOH = −2.5 мА.
- Ёмкость входа 6/8 пФ (тип/макс), выхода 8/12 пФ (DS, с. 23).

Выход 5.8 мА слабее типичного драйвера шины ISA (74LS245, 24 мА), поэтому данные выводим на шину через буфер
(см. [architecture.md](architecture.md)).

## Ресурс

- **100 000 циклов стирания на каждый блок**, 1.6 млн на микросхему (DS, с. 1, 5, 16).
- Срок хранения данных в документе 290429-008 **не указан**.

## Команды (DS, табл. 3, с. 14)

| Команда | Циклов | 1-й цикл: адрес, данные | 2-й цикл: адрес, данные |
|---|---:|---|---|
| Read Array / Reset | 1 | X, `FFh` | — |
| Intelligent Identifier | 3 | X, `90h` | чтение IA → IID |
| Read Status Register | 2 | X, `70h` | чтение → SRD |
| Clear Status Register | 1 | X, `50h` | — |
| Erase Setup / Erase Confirm | 2 | BA, `20h` | BA, `D0h` |
| Erase Suspend / Resume | 2 | X, `B0h` | X, `D0h` |
| Byte Write Setup / Write | 2 | WA, `40h` | WA, WD |
| Alternate Byte Write Setup / Write | 2 | WA, `10h` | WA, WD |

IA — `00000h` (код производителя) или `00001h` (код устройства); BA — любой адрес внутри стираемого блока;
WA — адрес записываемого байта. Остальные коды зарезервированы Intel, использовать их нельзя (DS, с. 14, примечание 6).

### Коды идентификации (DS, табл. 2, с. 12; с. 13)

- Производитель: **89h** (Intel).
- Устройство: **A2h** (28F008SA).

Для чтения кодов **не нужно** высокое напряжение на VPP (DS, с. 13). Это позволяет определять микросхемы при
отключённом VPP.

## Регистр статуса (DS, табл. 4, с. 18)

| Бит | Имя | 1 | 0 |
|---|---|---|---|
| SR.7 | WSMS | готов | занят |
| SR.6 | ESS | стирание приостановлено | стирание идёт или завершено |
| SR.5 | ES | ошибка стирания | стирание успешно |
| SR.4 | BWS | ошибка записи байта | запись успешна |
| SR.3 | VPPS | **VPP низкое — операция прервана** | VPP в норме |
| SR.2–0 | — | зарезервированы, маскировать | |

- Если установлены и SR.4, и SR.5 после попытки стирания — неверная последовательность команд (DS, с. 18).
- SR.3, SR.4, SR.5 сбрасываются только командой `50h` (DS, с. 15, 22).
- SR.3 не показывает уровень VPP постоянно: он проверяется только после команды записи или стирания и не
  гарантирован в зоне между VPPL и VPPH (DS, с. 18).
- Содержимое регистра защёлкивается по спаду OE# или CE#; для обновления нужно снять OE# или CE# (DS, с. 15).
  На шине ISA каждый цикл чтения сам формирует новый OE#.

## Алгоритмы

### Чтение
После включения питания или выхода из deep power-down микросхема сама находится в режиме Read Array (DS, с. 11).
После любой записи или стирания нужно явно подать `FFh` (DS, с. 22).

### Запись байта (DS, рис. 8, с. 21; AP-364)
1. Записать `40h` по адресу байта.
2. Записать данные по тому же адресу.
3. Опрашивать регистр статуса (чтение по любому адресу микросхемы) до SR.7 = 1.
4. Проверить SR.3 (VPP) и SR.4 (ошибка записи). При ошибке — `50h` и повтор или отказ.
5. После серии — `FFh`, затем сравнить записанное.

Запись может только переводить биты из 1 в 0. Внутренняя проверка ловит лишь «1, не ставшие 0» (DS, с. 16).
Значит, перед записью блок должен быть стёрт, а после записи данные нужно сверить чтением.

### Стирание блока (DS, рис. 6, с. 19)
1. Записать `20h` по адресу внутри блока.
2. Записать `D0h` по адресу внутри блока.
3. Опрашивать SR.7 до готовности (тип. 1.6 с, макс. 10 с).
4. Проверить SR.3, SR.4 + SR.5 (последовательность), SR.5 (ошибка стирания).
5. `FFh`, затем проверить, что весь блок читается как `FFh`.

### Определение микросхемы
`90h` → прочитать адреса `0` и `1` → ожидаем `89h`, `A2h` → `FFh`.

## Защита от случайной записи

1. **VPP ≤ 6.5 В** — содержимое изменить невозможно, это главный аппаратный замок (DS, с. 7, 11, 25).
   Intel прямо предлагает делать VPP коммутируемым (DS, с. 11, раздел 2.2; AP-359, с. 3-555).
2. **RP# = 0** — запрет записи и сброс автомата (DS, с. 7). Intel рекомендует подключать RP# к POWERGOOD или
   системному сбросу (DS, с. 12, 17). Это же нужно, чтобы после сброса компьютера во время записи микросхема
   вернулась в режим чтения, а не отдавала регистр статуса (DS, с. 12, раздел 3.4).
3. **VCC < VLKO** — все функции запрещены (DS, с. 11).
4. **Двухшаговые команды** записи и стирания (DS, с. 11).
5. **Блокировка WE#** логикой платы. Без неё случайная запись в окно может перевести микросхему в режим статуса или
   ID — это не портит данные, но ломает чтение до команды `FFh` (AP-359, с. 3-557, рис. 7).

Защиты отдельных блоков (lock bits) у 28F008SA нет: в таблице команд их нет.

## Внутрисистемное программирование

Да, микросхема рассчитана на это: VPP = 12 В от системы, команды записываются обычными циклами процессора
(DS, с. 10–11). Ограничение: пока идёт запись или стирание, микросхема выдаёт регистр статуса вместо данных,
поэтому **код программатора должен выполняться из ОЗУ**, а не из самой флеш-памяти (DS, с. 10).

## Требования к питанию на плате

- 0.1 мкФ керамика между каждым VCC и GND и между VPP и GND, как можно ближе к выводам (DS, с. 17).
  AP-359 даёт расчёт: минимум 0.01 мкФ на VCC и 0.033 мкФ на VPP (с. 3-558–3-559).
- 4.7 мкФ электролит на каждые 8 микросхем (DS, с. 17).
- Дорожку VPP разводить как питание, той же ширины, что VCC (DS, с. 22, раздел 8.4).
- Порядок подачи VCC и VPP не важен (DS, с. 22).
