# Архитектура

Статус: **схема rev A нарисована** ([hardware/kicad/](../hardware/kicad/), PDF — [schematic.pdf](schematic.pdf)),
ERC без нарушений, нетлист сверен с таблицей соединений. **В железе не проверялась**, платы ещё нет.

## Исходные условия

- Микросхемы снимаются с модуля и ставятся на карту по отдельности: **1 или 2 × PA28F008SA**, то есть 1 или 2 Мбайт.
  Модуль целиком не используется ([original-module.md](original-module.md)).
- Карт будет много, поэтому важны простая сборка, доступные детали и отсутствие ручной подгонки.
- Цели: IBM PC XT (8088, 4.77 МГц), AT (80286), 386, 486; загрузка DOS с карты; запись из DOS.

## Варианты доступа

### A. Окно памяти с банками (memory mapped)

В адресном пространстве ПК открывается окно фиксированного размера. Регистр банка в порту ввода-вывода выбирает,
какой кусок флеш-памяти виден в окне. Процессор читает флеш обычными командами `MOV`/`MOVS`, команды флеш
(`40h`, `20h/D0h`…) пишутся в окно обычной записью в память.

### B. Доступ через порты (I/O mapped)

Адрес флеш-памяти записывается в регистры-защёлки (или счётчик с автоинкрементом) через порты, данные читаются
и пишутся через порт данных. В памяти карта не видна.

### Сравнение

| Критерий | A — окно памяти | B — порты |
|---|---|---|
| Регистры адреса | 1 × 8 бит (номер банка) | 20–21 бит: 3 защёлки или 5 счётчиков 74HCT161 |
| Загрузка DOS | ПЗУ лежит в той же флеш и видно в окне при сбросе | **Всё равно нужно окно памяти** для Option ROM: отдельная EEPROM + свой дешифратор |
| Итог по микросхемам | меньше | больше: адресные регистры + ПЗУ + дешифратор ПЗУ |
| Адресное пространство | окно 8 Кбайт в C8000h…F4000h + 8 портов | 8 Кбайт под ПЗУ + несколько портов — столько же |
| Скорость чтения на 8088 | `REP MOVSW` из окна | цикл `IN AL,DX` / `STOSB` / `LOOP` на каждый байт |
| Совместимость | риски общие для любых ПЗУ в C8000h…EFFFFh: shadow, EMM386, −MEMCS16 | те же риски из-за ПЗУ |
| Программы | проще: обычные указатели | проще только запись в порт данных |

Оценка скорости по числу тактов 8088 (не измерение): цикл `IN`/`STOSB`/`LOOP` тратит на байт примерно вдвое больше
тактов процессора, чем `REP MOVSW`, а шина ISA в обоих случаях успевает. Реальную скорость меряем на этапе 2.

Главный аргумент: **загрузка DOS требует Option ROM, а Option ROM требует окна в памяти**
(XT 5-10, см. [isa-interface.md](isa-interface.md)). Вариант B не избавляет от окна, а только добавляет
адресные регистры и отдельную микросхему ПЗУ.

### Решение: вариант A

Окно **8 Кбайт**, регистр банка 8 бит, ПЗУ карты хранится в начале самой флеш-памяти.

Почему 8 Кбайт, а не 16 или 32:

- занимает столько же верхней памяти, сколько обычное ПЗУ XT-IDE, — меньше конфликтов;
- 8 бит регистра ровно покрывают 2 Мбайт: 7 бит — номер банка внутри микросхемы (1 Мбайт / 8 Кбайт = 128),
  1 бит — выбор микросхемы;
- смена банка — одна команда `OUT`; при секторе 512 байт она нужна раз в 16 секторов.

## Структура карты

```
              ISA 8 bit
 SA19..SA13 ──► [74HCT688] ◄── SW1 (5 переключателей)  → MEM_HIT#
 SA9..SA3, AEN ► [74HCT688] ◄── SW2 (6 переключателей) → IO_HIT#
 SA2..SA0, IO_HIT#, IOW# ► [74HCT138] → BANK_WR#, CTRL_WR#

 D7..D0 ──► [BANK 74HCT273] → FA13..FA19 (обе флеш), CHIP (бит 7)
 D1..D0 ──► [CTRL 74HCT175] → WE_EN, VPP_EN
 RESET DRV ─► инвертор → сброс BANK и CTRL, RP# обеих флеш

 SA12..SA0 ─────────────────────────► A12..A0 флеш
 MEM_HIT#, CHIP ─► логика ─► CE0#, CE1#
 SMEMR# ─────────────────────────────► OE# флеш, DIR буфера
 SMEMW#, WE_EN ─► логика ─► WE# флеш
 D7..D0 ◄──► [буфер 245] ◄──► DQ7..DQ0 флеш

 +12 V ──[JP1 WRITE]──[P-MOSFET]──► VPP обеих флеш ── 10 кОм → GND
                          ▲
                   VPP_EN (через транзистор)
```

Типы логики (HCT) выбраны потому, что все входы видят ТТЛ-уровни шины ISA.
Буфер данных — 74LS245: ток IOL 24 мА, как у буферов самой шины IBM (TI, SDLS146B, с. 3).

Логику дешифрации и регистр управления можно свернуть в одну ATF22V10C (GAL22V10), но тогда каждую карту нужно
прошивать программатором. Rev A делается на 74HCT, чтобы её мог повторить любой.

### Логика

```
~MEM_HIT = (SA19..SA13 == 1,1,SW1)            74HCT688 U3
~IO_HIT  = (SA9..SA3, AEN == 1,SW2,0)          74HCT688 U4
~BANK_WR = ~IO_HIT & ~IOW & SA2..0 == 0        74HCT138 U5, Y0
~CTRL_WR = ~IO_HIT & ~IOW & SA2..0 == 1        74HCT138 U5, Y1
~CE0     = ~MEM_HIT | CHIP                     74HCT32 U9A
~CE1     = ~MEM_HIT | ~CHIP                    74HCT32 U9B
~FWE     = ~SMEMW  | ~WE_EN                    74HCT32 U9C
~OE      = ~SMEMR                              обе флеш
~RP      = ~RST = NOT RESET_DRV                74HCT04 U10A; также сброс U6, U7
```

Буфер U8 включён, пока адрес внутри окна. Направление задаёт −SMEMR: при чтении данные идут с флеш на шину,
в остальное время — с шины на флеш. Поэтому после снятия −SMEMW буфер не отключается, и данные на выводах флеш
держатся, пока держит шина. Хватает ли этого для tWHDX = 5 нс — проверка на этапе 2 ([testing.md](testing.md)).

### Правило банка 0

Ctrl-Alt-Del на XT и AT перезапускает BIOS **без** сигнала RESET DRV, поэтому регистры BANK и CTRL не сбрасываются.
Чтобы BIOS после тёплой перезагрузки снова нашёл ПЗУ, программы обязаны соблюдать правило:

- вне собственного кода в регистре BANK всегда `00h`, в CTRL — `00h`, флеш в режиме Read Array;
- обработчик INT 13h восстанавливает это состояние перед каждым возвратом;
- утилиты восстанавливают его при выходе, по Ctrl-C и Ctrl-Break;
- Option ROM при инициализации записывает `00h` в оба регистра.

## Регистры

| Порт | Имя | Доступ | Биты | После сброса |
|---|---|---|---|---|
| base+0 | BANK | запись | 6..0 — банк 8 Кбайт внутри микросхемы (флеш A19..A13); 7 — микросхема (0 = U1, 1 = U2) | `00h` |
| base+1 | CTRL | запись | 0 — WE_EN (разрешить WE# флеш); 1 — VPP_EN (включить VPP); 7..2 — писать 0 | `00h` |
| base+2…+7 | — | — | зарезервированы | |

Регистры только на запись: так меньше деталей. Карта определяется программно — по сигнатуре ПЗУ в окне
и по кодам флеш `89h/A2h`. Как определить положение перемычки без порта чтения — в [programming.md](programming.md).

Базовые адреса и раскладка флеш — в [memory-map.md](memory-map.md).

## Защита от записи

Четыре независимых уровня. По умолчанию запись **аппаратно заблокирована**.

| Уровень | Как работает | По умолчанию | Основание |
|---|---|---|---|
| 1. Перемычка JP1 «WRITE» | разрывает цепь +12 В → VPP; VPP стягивается резистором к GND | **снята** | при VPP ≤ 6.5 В содержимое изменить нельзя (DS с. 7, 25) |
| 2. Бит VPP_EN | включает ключ VPP; сбрасывается RESET DRV | 0 | Intel рекомендует коммутируемый VPP (DS с. 11; AP-359 с. 3-555) |
| 3. Бит WE_EN | без него WE# флеш всегда высокий: никакая запись в окно не доходит до флеш | 0 | гейтирование WE# (AP-359 с. 3-557, рис. 7) |
| 4. RP# = инверсия RESET DRV | при сбросе и включении питания флеш заблокирована, автомат сброшен | — | RP# к системному сбросу или POWERGOOD (DS с. 12, 17) |

Плюс двухшаговые команды флеш и подтверждение в утилитах.

Уровень 4 нужен не только для защиты: если компьютер сбросить во время записи, флеш без сигнала RP# осталась бы
в режиме регистра статуса, BIOS не нашёл бы ПЗУ, и карта «исчезла» бы до выключения питания (DS с. 12, раздел 3.4).

Без перемычки JP1 записать флеш невозможно никакой программой, в том числе вирусом или ошибкой в драйвере.

## Цепь VPP

- Источник — +12 В шины ISA (B9). Допуск блоков питания IBM +5 % / −4 % = 11.52…12.60 В, флеш требует
  11.4…12.6 В ([isa-interface.md](isa-interface.md)). Запас снизу 120 мВ.
- Ключ — P-MOSFET в плюсовой цепи, как в AP-359 (рис. 3, с. 3-555). Расчёт Intel: 60 мА × 0.6 Ом = 0.04 В падения.
  Требования к нашему транзистору: RDS(on) ≤ 0.5 Ом при VGS = −10 В, VDS ≥ 20 В, допустимое VGS не меньше ±20 В
  (затвор переключается на полные 12 В) — либо делитель в затворе, ограничивающий VGS.
- 10 кОм с VPP на GND: при снятой перемычке или выключенном ключе VPP гарантированно ниже 6.5 В.
- Развязка VPP: 0.1 мкФ у каждой микросхемы (DS с. 17).
- Светодиод «VPP» на выходе ключа: горит, пока на флеш подано напряжение записи.

### Главный риск — блоки питания клонов

Если +12 В на конкретной машине ниже 11.4 В или выше 12.6 В, писать нельзя: запись становится ненадёжной,
а выше 12.6 В микросхема может пострадать (AP-359, с. 3-554). Флеш это не обнаружит: бит SR.3 не гарантирован
между 6.5 и 11.4 В (DS с. 18).

Мера первой версии: перед записью измерить +12 В на контрольной точке карты (методика в [testing.md](testing.md)).
Если на практике окажется, что многие машины выходят за допуск, на следующей ревизии ставим собственный
стабилизированный источник 12 В от +5 В. Intel перечисляет такие решения в AP-359 (табл. 1, с. 3-555),
например MC34063A.

## Загрузка DOS

Подробности — этап 4. Решения, принятые сейчас, потому что они влияют на железо:

1. **ПЗУ в начале флеш.** После сброса BANK = 0, в окне видны первые 8 Кбайт микросхемы U1 — там образ ПЗУ
   с сигнатурой `55AAh`. BIOS находит его при сканировании (XT 5-10).
2. **Резидентная часть копируется в ОЗУ.** Код в окне пропадает при первой же смене банка, поэтому обработчик
   INT 13h не может выполняться из окна. При инициализации ПЗУ отнимает 2 Кбайт у верхней границы основной
   памяти (слово 40h:13h), копирует туда обработчик и перехватывает INT 13h.
3. **Эмуляция жёсткого диска.** Карта становится диском 80h, если других жёстких дисков нет (это основной
   сценарий — XT без винчестера). Если диск 80h уже есть, первая версия подключает флеш как следующий диск,
   без загрузки с неё. Перестановку дисков — позже.
4. **Запись через INT 13h (ПЗУ 1.1, формат диска 2).** Блок стирания 64 Кбайт, а сектор 512 байт, и буфера
   64 Кбайт у ПЗУ нет. Поэтому данные диска хранятся инвертированными: стёртая флеш читается как нули, и запись
   в свободное место только сбрасывает биты — она программируется на месте. Если бит должен стать 1, блок
   переписывается через запасной блок (последний блок флеш). Без JP1 запись возвращает AH = 03h
   «защита от записи», ничего не меняя. Подробности — [programming.md](programming.md).

Схема загрузки на конкретных BIOS (XT 1982 и 1986, AT, Award/AMI/Phoenix для 386/486) проверяется на этапе 4.
В частности, ещё не подтверждено, пробует ли каждый BIOS загрузку с 80h сам или ПЗУ должно перехватить INT 19h.

## Программы

DOS ограничивает имена файлов форматом 8.3, поэтому имена из задания сокращены:

| Задание | Файл | Что делает |
|---|---|---|
| FLASHINFO.EXE | `FLINFO.EXE` | поиск карты, ID микросхем, объём, состояние перемычки |
| FLASHREAD.EXE | `FLREAD.EXE` | чтение всей флеш или диска в файл |
| FLASHWRITE.EXE | `FLWRITE.EXE` | запись образа с проверкой |
| FLASHFORMAT.EXE | `FLFORMAT.EXE` | разметка диска и загрузочная структура |
| Option ROM | `FLASHROM.BIN` | INT 13h и загрузка |

Инструменты: **NASM** для ПЗУ и **Open Watcom C** (16-битная модель, код 8086) для утилит. Оба работают на
современном ПК и собирают программы под DOS; проверка — в эмуляторе (86Box) и на железе.
